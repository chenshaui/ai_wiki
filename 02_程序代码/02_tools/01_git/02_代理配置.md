# 1. 问题
发现git还是无法正常联网，报端口 443 错误，由于git也需要设置代理。

![](.02_443端口超时_images/问题.png)

# 2. 解决方法

使用Git bash工具运行命令 (注意修改成自己的IP和端口号，在代理的设置里查看)

![](.02_代理配置_images/代理的端口号.png)

```shell
# 注意修改成自己的IP和端口号
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890
```

取消代理

```shell
# 取消代理
git config --global --unset http.proxy
git config --global --unset https.proxy

# 查看代理
git config --global --get http.proxy
git config --global --get https.proxy
```

# 3. 给不同的git服务商配置不同代理

当前生效的是仓库本地的 Git 配置文件 [`.git/config`](</代码仓的.git/config>)。

核心配置只有两段：
```ini
[http]
    version = HTTP/1.1

[http "https://github.com/"]
    proxy = http://127.0.0.1:7890
    sslVerify = true
```

含义是：
- `http.version = HTTP/1.1`
  - 让 Git 的 HTTP 传输固定用 `HTTP/1.1`，这是为了兼容你本地这个代理。
- `[http "https://github.com/"]`
  - 这是 URL 定向配置，只对前缀匹配 `https://github.com/` 的远端生效。
- `proxy = http://127.0.0.1:7890`
  - 只有访问 GitHub HTTPS 仓库时，Git 才会通过本地 `7890` 代理。
- `sslVerify = true`
  - 访问 GitHub 时仍然校验证书，没有关闭 TLS 校验。

现在的行为可以简单记成：
- 用代理：
  - `https://github.com/...`
- 不用代理：
  - `https://gitee.com/...`
  - `https://*.amazonaws.com/...`，比如 CodeCommit
  - 其他所有非 GitHub 的 HTTPS Git 远端
  - 所有 SSH 远端，例如 `git@github.com:...`、`ssh://...`

补一句：这是“当前仓库专用”配置，不是全局 Git 配置，所以只影响这个仓库。
